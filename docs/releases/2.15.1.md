# OpenVitals 2.15.1

Released 2026-10-23.

This release lets the medical records import open a zip of FHIR files, the kind CommonHealth exports, and makes a file that cannot be imported explain why. The new report names each file and what was found in it, never the records themselves, so it can be shared to get a problem fixed without sharing your medical data.

### Added

- **A report when a file cannot be imported.** When the medical records import refuses a file, the screen now offers a report to copy or save. It says what stopped the import and what the file holds, a zip's files each on a line of their own: the size and kind of each, and for JSON its shape and record types, or the line and column where it stops being valid JSON. It holds no value from the file, only names, sizes and structure; check the file names before you share it. When nothing in a file can be added, the review offers the report of what was held back and why, which, like the report after an import, includes the records.

### Fixed

- **A zip of FHIR files can be imported.** The medical records import read a zip only as an Apple Health export or a set of CDA documents, so a zip of FHIR JSON files, as CommonHealth exports, was refused as a file OpenVitals can't read. Each JSON, NDJSON or text file in such a zip is now read as a picked FHIR file is, whatever its folders. A file in it that is not FHIR is left out and counted in the review, the report names it with what it holds, and the rest are imported. Reported in #294.

The app keeps the same package name and signing certificate, so this installs as a normal update.

Distribution flow:

- GitHub release with signed APK, signed debug APK, and signed Android App Bundle assets.
- Direct Google Play production upload from the approved production run of the release workflow.
